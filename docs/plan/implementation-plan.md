## 2. 贯穿工作（每阶段都做）

- **契约测试先行**：越界矩阵、黑名单用例、预算边界、版本冲突、确认令牌、schema 越界。用例清单是仓库结构的一部分，不是阶段四产物。
- **观测**：审计事件（§4.4.3 结构）、调用指标、结构化日志；日志不得含参数值明文。
- **CI 门禁**：常驻 token 实测、golden 集回归、模板 SQL 静态检查、审计链校验作业。
- **回退开关**：每个面向调用方的行为（渐进发现、模板分发、平铺阈值）都由服务端开关控制，可单独关闭回落到上一阶段行为。写路径的回退粒度是「全局 → 租户 → 组 → 数据源 → 能力」逐级关闭：任一关闭后新写立即拒绝，已提交数据不受影响；停止开放写不需要回滚代码。
- **文档同步**：结论进 `docs/`，理由与被否决项进 `notes/<module>/`（见仓库根 `AGENTS.md`）。

**门禁 G5**（W5.1–W5.7 全部完成）：

1. 五级开关默认全关；未开时写能力不进入可见集、调用 100% 被拒（不可见 → `MCP_CAPABILITY_NOT_FOUND`，可见但运行期开关关闭 → `MCP_WRITE_DISABLED`），不存在降级为只读执行的路径。
2. 写账号自检 W1–W7 全绿；人为给写账号加 `CREATE` 权限后启动必须失败（用例）。
3. 写校验矩阵全绿：多语句、无 WHERE、退化 WHERE、DDL/TRUNCATE/GRANT、黑名单函数、越界列、越界表、字面量值、`RETURNING *` 均拒绝且零放行。
4. 令牌契约全绿：单次、300s TTL、六元绑定、吊销立即生效、参数变化失效。
5. 行数上限：超限事务回滚，DB 侧断言行数未变；不发生"截断写入"。
6. 幂等与并发：同键同参重放、同键异参拒绝、并发双 apply 只成功一次、乐观锁未命中不重试。
7. 四眼：提交人=批准人 0 通过；批准过期后 apply 拒绝；撤销权限后下一次 apply 拒绝。
8. 审计：`write_intent` 与 `write_apply`/`write_failed` 一一对应；哈希链校验通过；审计中无参数明文。
9. 提交未知：断连/超时场景返回 `MCP_WRITE_OUTCOME_UNKNOWN`，无自动重试、无换连接重放。
10. staging 环境端到端可用（内测租户），指标口径可复算；生产写仍默认关闭，开放与否由 D10 决定。

## 3.1 非功能目标（阶段〇确认，未确认项标注待定）

| 项 | 目标 | 来源 |
|---|---|---|
| 部署形态 | 容器化，K8s 内网；与 Harness 平台单向调用 | 平台方（W0.7） |
| 单实例 QPS | 待定：以平台侧峰值 ×1.5 定容 | 平台方（W0.7） |
| 延迟 | 元工具 p95 < 300 ms；目录/检索响应 p95 < 800 ms（不含 DB 执行） | 本仓库设定，平台方确认 |
| 数据面超时 | 读受 `statement_timeout` 与 §5 预算约束；写另加 `lock_timeout`（默认 2000ms），不设额外的服务端硬编码 | 本仓库 |
| 可用性 | 与 Harness 平台同级（阶段目标 99.5%） | 平台方 |
| 故障隔离 | 单数据源不可用不影响目录、检索与其他数据源调用 | 本仓库 |
| 限流 | 读：按租户 + 按能力组；写：租户/会话/能力/数据源 + 日影响行数 + 并发写事务；拒绝优先于排队 | 本仓库，阈值待 W0.7；写侧默认值见 `docs/plan/write-path.md` §10 |

### 3.2 技术栈（已定稿）

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | Rust（edition 2024）+ tokio + JSON-RPC（stdio / streamable-http 双入口） | 手写 JSON-RPC 协议层，stdio 与 streamable-http 双入口；未采用 rmcp |
| 持久化 | rusqlite（审计、能力注册表） | 追加表 + 哈希链，不引入独立数据库 |

| 前端 | React + TypeScript + Vite | 仅管理台三个页面 + 健康页，不含工具调试器 |

## 4. 每阶段共同 DoD

1. 面向调用方的行为变更都有服务端开关与回退验证步骤。
2. 新增/修改规则附带契约测试用例，CI 全绿。
3. 审计事件字段完整（谁、对什么、用什么版本、结果如何）。
4. 预算与指标有当阶段实测数字，不用估算值替代。
5. `docs/` 结论已更新，`notes/` 记录理由与被否决项。

## 5. 主要风险与回退

| 风险 | 触发信号 | 回退 |
|---|---|---|
| 客户端不支持动态工具集比例过高 | 阶段〇矩阵显示 >50% 客户端不支持 | 主路径转静态分组注入（§5.2），G1 目标按客户端重定 |
| 模板审核成为瓶颈 | 审核队列积压 > SLA | 扩大策略自动审批范围（仅 `read` 且无敏感列）；不降低审核强度 |
| 只读账号无法满足（存在必须写的运维查询） | W0.6 清单出现写需求 | 写需求走阶段五独立审批通道，不并入只读面；阶段五之前保持拒绝 |
| token 基线高于预算 | W0.5 实测常驻 >2,000 | 先砍组索引与元工具描述，再考虑降级到分组注入 |
| 检索准确率不达标 | recall <85% | 提高关键词权重、改用业务词典；不改预算口径 |
| 数据源方言差异暴露 | 阶段三出现方言特例分支 | 差异下沉到 `executor`，模板正文保持方言无关 |
| 目标环境/网络未就绪 | W0.7 逾期或 staging 连不通数据源 | 契约测试在本地容器编排环境先跑；G1 标注"预验收"，生产可用性判定顺延至环境就绪 |
| 写能力误伤在线业务（长事务/锁等待） | `lock_timeout` 命中率 >1% 或写 p95 延迟超目标 | 关闭该数据源写开关（`[datasources.write] enabled=false`）；收紧 `statement_timeout_ms`/`max_affected_rows`；不改读路径 |
| 写账号权限过大 | 启动自检 W2/W3/W6 失败，或每日权限漂移巡检发现 DDL/superuser | 拒绝启动（fail-closed）；由 DBA 收回权限后重启；期间该数据源写能力不可用，读不受影响 |
| 审批被绕过或四眼失效 | 同人批准计数 >0、或 `write_apply` 缺 `approval_id` | 立即关闭对应能力开关并吊销在途令牌；审计回溯已执行意图；修复前不恢复 |
| 令牌重放/参数替换 | 重放类 `MCP_CONFIRM_TOKEN_INVALID` 计数 >0 且非客户端重试 | 全局关闭写（`HJZL_MCP_WRITE_ENABLED=false`），吊销全部令牌，排查会话绑定 |
| 幂等键失效导致重复写 | 同 `(actor, capability, params_hash)` 短窗口内多次 `applied` | 关闭该能力；要求客户端修复幂等键生成；重复写由人工补偿，不自动回滚 |
| 生产误开写 | 全局/租户开关变更审计与发布记录不一致 | 关闭全局开关并收回写账号 DSN 环境变量；已提交数据按 D6 审计链路追溯 |
| 写能力把 PII 写入可读表 | 审核期列白名单检查通过但语义漏判 | 关闭能力，按数据源级 `forbidden_write_columns` 加列后重审；不依赖事后清理 |
