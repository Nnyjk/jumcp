## 2. 贯穿工作（每阶段都做）

- **契约测试先行**：越界矩阵、黑名单用例、预算边界、版本冲突、schema 越界、builtin 不可改。用例清单是仓库结构的一部分，不是阶段四产物。
- **观测**：审计事件（§4.4.3 结构）、调用指标、结构化日志；日志不得含参数值明文。
- **CI 门禁**：常驻 token 实测、golden 集回归、模板 SQL 静态检查、审计链校验作业。
- **回退开关**：每个面向调用方的行为（渐进发现、模板分发、平铺阈值）都由服务端开关控制，可单独关闭回落到上一阶段行为。自维护通道的回退粒度是「停止维护 agent 写入 → 保留已发布版本」：关闭后草案仍可审，但不再产生新草案；已发布工具不受影响。
- **文档同步**：结论进 `docs/`，理由与被否决项进 `notes/<module>/`（见仓库根 `AGENTS.md`）。

### 阶段一：只读面 + 裁剪 + 审计（第 1–5 周，与阶段〇后半重叠）

| 编号 | 工作包 | 交付物 | 完成定义 |
|---|---|---|---|
| W1.1 | 入口与鉴权 | Header / `_meta` / profile 三通道解析、越界判定（`strict`）、身份注入 | 越界请求 100% 返回 `MCP_GROUP_FORBIDDEN` + `offending_groups` |
| W1.2 | 组模型与角色映射 | 组定义（≤20）、角色 allowlist、预算上限 | 组配置可热加载，非法配置拒绝启动 |
| W1.3 | `db_query_readonly` | L1–L4 全链、`max_rows` 夹紧、`cell_char_limit/offset`、`allowed_schemas` 越界拒绝 | 写语句/可写 CTE/黑名单函数全部拒绝；越界 schema 返回 `MCP_SCHEMA_OUT_OF_SCOPE` |
| W1.4 | 启动自检 | 只读账号写操作必须失败、DSN 锁生效、`statement_timeout` 生效 | 自检失败即拒绝启动（fail-closed） |
| W1.5 | 审计 | 追加表 + 哈希链 + 每日校验；`admin_change` 结构预留 | 篡改一行可被校验作业发现 |
| W1.6 | 审批最小版 | 单审阻断 `draft → published` | 未审批模板无法进入 `published` |
| W1.7 | 契约测试套件 | 用例集接入 CI | 新增规则必须同时新增用例 |
| W1.8 | 配置与密钥 | 租户策略来源（配置中心/DB）、数据源只读凭证注入、凭证轮换 | 日志/审计/模型上下文中检索不到凭证；轮换不需改代码 |
| W1.9 | 可观测与部署 | 指标（调用数/拒绝原因/预算/token/延迟）、审计查询最小接口、镜像与部署脚本、灰度开关 | staging 可完成 G1 全部验收项；指标与审计可查 |

**门禁 G1**：内测组可用；常驻定义实测 ≤2,000；越界零静默降级；审计链校验通过。

### 阶段二：渐进发现（第 6–9 周）

| 编号 | 工作包 | 交付物 | 完成定义 |
|---|---|---|---|
| W2.1 | 元工具三件套 | `search_capabilities` / `describe_capability` / `list_groups` | 检索结果不含完整 schema；不可见与不存在同构 |
| W2.2 | 可见集过滤与检索 | 硬过滤 → 关键词 + 向量混合 → 三重缓存 | golden 集 Top-5 recall ≥85% |
| W2.3 | 预算判定 | 默认 `fail`、`truncate` 可选、摘要模式、会话累计计量 | 超限返回 `MCP_BUDGET_EXCEEDED` 并附可执行建议 |
| W2.4 | 静态客户端降级 | 分组注入 + 平铺阈值（≤40） | 降级路径有独立基线，不套用 7,500 |
| W2.5 | A/B 回归 | 与阶段〇基线对比报告 | 工具选择准确率不低于基线 |

**门禁 G2**：峰值 ≤8,000（支持动态注入的客户端）、recall 与准确率达标、降级路径可用。

### 阶段三：注册表与分发（第 10–14 周）

| 编号 | 工作包 | 交付物 | 完成定义 |
|---|---|---|---|
| W3.1 | capability 存储 | 双布尔 + 版本 + `definition_hash` + `annotations` | 已发布定义不可原地修改（数据库约束级） |
| W3.2 | 模板校验门禁 | AST 单语句、三类结构变体白名单、`allowed_schemas`、参数类型校验 | 违规模板注册即拒绝 |
| W3.3 | `db_run_template` | 版本钉住、约束执行、预检缓存、结果缓存 | 会话内换版本返回 `MCP_VERSION_CONFLICT` |
| W3.4 | `invoke_capability` | 统一分发链 + `http`（base URL 白名单、禁跨 host 重定向）+ `kb` 执行器 | `template` kind 被拒（`MCP_USE_DB_RUN_TEMPLATE`） |
| W3.5 | 授权租约 | 租约签发/校验/撤销 | 撤销后下一次调用立即失效 |
| W3.6 | 首批模板 | 20–30 个真实业务模板 | 全部走完审核并在内测组可用 |

**门禁 G3**：模板占 DB 类调用 ≥40%；静态客户端上 `endpoint` 类可发现且可调用（契约测试）；模板 SQL 静态检查覆盖 100%。

### 阶段四：治理闭环与规模化（第 15–19 周）

| 编号 | 工作包 | 交付物 | 完成定义 |
|---|---|---|---|
| W4.1 | Admin API + 管理台 | admin 接口集、薄前端（审核队列/例外/审计查询） | UI 无直连库路径；写操作全部产生 `admin_change` |
| W4.2 | 审批流 | 策略自动 + 高风险人工、SLA 计时 | 发布必须填写外部审批单号，提审人与批准人分别落审计 |
| W4.3 | 聚类与草案流水线 | 指纹归一化、聚类、草案生成 | 采集→草案 ≤1 个工作日（系统侧） |
| W4.4 | 评估自动化 | EXPLAIN / PII / 成本 / 参数合理性检查 | 任一项不过则不能提审 |
| W4.5 | 灰度与淘汰 | 命中率/错误率看板、`deprecated` + `successor_id` | 低频模板自动进入观察队列 |

**门禁 G4**：admin 变更审计覆盖 100%；模板占比 ≥60%；审批 SLA 达标。

### 阶段五：自维护通道（第 20–24 周）

只写本项目自有数据（能力注册表），不写任何接入数据源；可修改面与不变量见主文档 §4.4.6。

| 编号 | 工作包 | 交付物 | 完成定义 | 依赖 |
|---|---|---|---|---|
| W5.1 | 单一事实源 | 启动时把注册表投影为发现面目录（含 builtin），变更后刷新；新增 `source=builtin\|managed` | 新建/修改/下架后，新会话 `search_capabilities` 立即反映；builtin 不进维护候选 | 阶段三 W3.1 |
| W5.2 | 维护 MCP 工具组 | `admin` 组：`capability_stats` / `capability_create` / `capability_update` / `capability_deprecate`；HTTP 等价路由 | 只产 `draft`；对 builtin 一律 `MCP_BUILTIN_IMMUTABLE`；每次变更落 `admin_change` | W5.1、W4.2 |
| W5.3 | 调用历史聚合 | 按 `sql_hash` / `params_hash` 的频次、失败率、p95、N 日未用；只读 | 维护 agent 一次调用可取到候选清单；口径写入文档 | W1.5 |
| W5.4 | 草案生成与去重 | 由聚合结果生成 draft；`(group, sql_fingerprint, params_shape)` 幂等 | 重复触发不产生重复草案；草案带来源指纹与频次证据 | W5.2、W5.3 |
| W5.5 | 定时触发 | 平台侧 cron 拉起维护 agent；服务侧不内建调度 | 连续两轮运行不产生重复草案；维护失败不阻塞读面 | W5.4 |

**门禁 G5**（W5.1–W5.4 全部完成）：

1. builtin 零变更：维护通道对 5 个常驻工具的 create/update/deprecate 全部被拒绝。
2. 端到端：维护 agent 读聚合 → 产 draft → 人工审核并填写外部审批单号 → **新会话** `search_capabilities` 命中并成功调用。
3. 审计：create/update/deprecate 与 publish 各自产生 `admin_change`，按 `template_id + version` 可回放。
4. 幂等：同一指纹连续两轮触发只保留一个 draft。
5. 只读不变量：全仓不存在写数据源的执行路径；只读自检保持现状。

## 3.1 非功能目标（阶段〇确认，未确认项标注待定）

| 项 | 目标 | 来源 |

| 部署形态 | 容器化，K8s 内网；与 Harness 平台单向调用 | 平台方（W0.7） |

| 数据面超时 | 读受 `statement_timeout` 与 §5 预算约束，不设额外的服务端硬编码 | 本仓库 |

| 故障隔离 | 单数据源不可用不影响目录、检索与其他数据源调用 | 本仓库 |
| 限流 | 按租户 + 按能力组；维护通道按 agent + 每日草案数；拒绝优先于排队 | 本仓库，阈值待 W0.7 |

## 4. 每阶段共同 DoD

1. 面向调用方的行为变更都有服务端开关与回退验证步骤。
2. 新增/修改规则附带契约测试用例，CI 全绿。
3. 审计事件字段完整（谁、对什么、用什么版本、结果如何）。
4. 预算与指标有当阶段实测数字，不用估算值替代。
5. `docs/` 结论已更新，`notes/` 记录理由与被否决项。

## 5. 主要风险与回退

| 风险 | 触发信号 | 回退 |
|---|---|---|
| 客户端不支持动态工具集比例过高 | 阶段〇矩阵显示 >50% 客户端不支持 | 主路径转静态分组注入（§5.2），G1 目标按客户端重定 |
| 模板审核成为瓶颈 | 审核队列积压 > SLA | 扩大策略自动审批范围（仅 `read` 且无敏感列）；不降低审核强度 |
| 只读账号无法满足（存在必须写的运维查询） | W0.6 清单出现写需求 | 该需求不属于本服务：不提供写面，也不降级为写连接；由平台或业务系统自行承接 |
| token 基线高于预算 | W0.5 实测常驻 >2,000 | 先砍组索引与元工具描述，再考虑降级到分组注入 |
| 检索准确率不达标 | recall <85% | 提高关键词权重、改用业务词典；不改预算口径 |
| 数据源方言差异暴露 | 阶段三出现方言特例分支 | 差异下沉到 `executor`，模板正文保持方言无关 |
| 目标环境/网络未就绪 | W0.7 逾期或 staging 连不通数据源 | 契约测试在本地容器编排环境先跑；G1 标注"预验收"，生产可用性判定顺延至环境就绪 |
| 维护 agent 产出噪声草案 | 审核队列积压 > SLA，或草案采纳率持续 <20% | 收紧聚合门槛、加每日草案配额、低价值草案自动过期；不降低发布审核强度 |
| 自维护工具定义被投毒 | 审核时字段级前后值中出现指令性描述或与 SQL 不符的参数说明 | 定义哈希钉住 + 变更重审 + builtin 不可改 + 发布必填外部审批单号；回滚到上一版本 |
| 发现面与注册表不一致 | 新建工具检索不到，或已下架仍可见 | 单一事实源投影 + 启动重建 + 变更后刷新 + 契约测试断言 |
| 维护通道成为提权面 | 维护 agent 身份出现 create/publish 以外的操作，或 builtin 变更记录 | admin 组独立角色 + 只产 draft + 全量 `admin_change`；异常即关闭维护通道 |
