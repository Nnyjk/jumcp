# 管理面用账号密码替代共享令牌

## 被否决的决定：继续用 `JUMCP_ADMIN_TOKENS`（`id:token` 列表）做管理面登录

外部约束是：部署方只有一个管理台、一到两名运营者，且要求在**不重启进程、不改环境变量**的前提下
完成「加人 / 停用某人 / 改口令」。共享令牌模型在这三件事上都要动环境变量并重启，而重启会中断
MCP 面正在跑的客户端；令牌本身也无法单独吊销——撤一个人等于把列表整体重发。

因此管理面改为单一账号体系：

- 账号存 `admin_users`（Argon2id 哈希、`state` 可停用），会话存 `admin_sessions(admin_user_id, …)`；
- 改口令或停用账号时在**同一事务**里删掉该账号的全部会话，所以吊销是即时的、只影响一个人；
- 空库首启用 `JUMCP_ADMIN_USERNAME` / `JUMCP_ADMIN_PASSWORD` 播种首个管理员，之后这两个变量失效，
  避免「环境变量里的口令」长期成为可用的旁路凭据。

## 坑

- `admin_sessions` 旧 schema 带 `token_id` 列。该表是临时会话，启动时若缺 `admin_user_id` 列就整表重建；
  `audit_events`、`upstreams`、`access_tokens`、能力表**不能**参与重建。
- 首次启动判定必须用「`admin_users` 表为空」，不能用「配置文件里没写变量」：容器滚动更新时变量一直都在，
  拿变量判断会导致每次启动都尝试播种。
- 登录失败的三种情形（账号不存在 / 口令错 / 账号停用）必须回同一句 message，否则接口变成账号枚举器；
  限流按提交的 `username` 计数也出于同一原因（按 IP 会在 NAT 后互相误伤，且无法保护单个账号）。
- 「会没有 active 管理员」的校验放在存储层事务里，而不是只放在 HTTP 层：删除自己被 HTTP 层先拦成
  `MCP_ADMIN_SELF_DELETE`，存储层的最后一名校验兜住其余路径（例如先改别人的 state 再删自己）。
